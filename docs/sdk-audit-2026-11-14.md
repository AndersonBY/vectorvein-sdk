# SDK audit and 0.3.92 corrections

The audit compared every SDK endpoint against exported backend routes at
`920d70bac1c706e15df0648d2ceadc20057540bf`, checked all synchronous/asynchronous
mixin signatures, reviewed the CLI and HTTP transport, and exercised serialization
and executable Python export for all 115 shipped workflow node classes.

## Corrected behavior

| Surface | Reproduction and correction |
| --- | --- |
| Cycle lists and details | Pagination fields caused `TypeError`; details also rejected `details_revision` and required the removed `title`. Models now accept the current response and cycle lists contain `AgentCycle` objects. `page_size` reaches the API and CLI. |
| Workspace summaries and files | Summaries no longer contain `agent_task_id`; file rows include revision/manifest fields and may omit timestamps. The SDK now accepts these shapes, retains write capabilities, builds nested file objects, and forwards file pagination and explicit task context. |
| Workflow tags | The backend returns `title`, `is_public`, `language`, and `color`, while the old model expected `name`. Tags now match the serializer. |
| Task configuration | Unset dataclass values were sent as `null`, overriding backend model defaults. Serialization now omits unset values while preserving `false`, zero, and empty collections. Reasoning, progress, resource-tier, Project, memory, email, and mount controls are available where the backend supports them. |
| Task results and user input | Task parsing discarded Project/Worktree identity, permissions, runtime state, costs, pending messages, and multiple-choice questions. Declared response fields now retain that information. |
| Access keys | List rows use a simple serializer without app details or records; nested rows previously remained dictionaries despite their advertised types. Lists/get/create now construct the declared key and VApp objects, with defaults for omitted simple-view details. Empty descriptions can be submitted when updating keys. |
| Workflow execution | Pending status responses contain objects, not output rows. Completed server-wait responses were polled again and full-scope output dictionaries could not be parsed. Pending responses now remain pending, completed results return directly, full output is preserved, and missing run IDs fail before polling. |
| HTTP transport | DRF HTTP authentication failures lacked the SDK envelope and were misclassified. HTTP errors now retain their status, HTTP errors cannot masquerade as success, extra headers are merged, and slash normalization avoids malformed paths. |
| JSON workflow import | Built-in ports were updated on a temporary node but never copied to the returned node. Imports now retain built-in and permitted dynamic ports, load serialized options before validating values, and preserve node flags. |
| Python workflow export | Falsy values and hidden ports were lost, quoted port names could produce invalid code, and skipped trigger edges caused lookup errors. These cases now survive export. Unknown execution nodes raise an error instead of silently disappearing. Scalar-valued port options can also be selected. |
| CLI uploads | `--upload-as single` rejected multiple files only after uploading them. The error is now detected before any upload. |
| Removed routes | `agent-workspace/sync-container-to-oss` and MCP tool create/update/delete do not exist in the backend. Their SDK methods, CLI commands, old fixtures, and sync documentation were removed. MCP tool list/get/logs remain available. |
| Quality gates | Incorrect argparse and heterogeneous-dictionary annotations caused the full type check to fail. An accurate help-kwargs type and corrected annotations restore the check; release CI now runs it. |

## Interface notes

- Use `WorkflowTag.title` and `AgentCycle.cycle_id`; the backend does not provide a
  cycle title. Cycle pagination uses `has_more` and `next_start_index`, with that
  index supplied as the next `cycle_index_offset` or CLI `--offset`.
- Flat cycle/file/access-key collections return the dataclasses declared by the
  public API. CLI JSON continues to normalize them to JSON objects.
- Project creation is explicit through `project_id`. Legacy workspace writes do
  not infer Project HEAD or Task Worktree ownership from a workspace ID.
- The removed workspace sync command has no replacement endpoint. Runtime
  checkpointing remains owned by the backend.

## Coverage and boundaries

All 208 remaining SDK endpoint targets are present in the reviewed snapshot of
379 registered backend routes, including aliases and inherited registrations.
The fixture records the actual exported routes rather than inferring them from
Python method names. Tests also check synchronous/asynchronous method and
signature parity.

The SDK does not provide a dedicated wrapper for every backend route. VApp
management, Cloud Storage, and explicit Project HEAD/Task Worktree APIs are
examples of remaining wrapper coverage; raw `vectorvein api request` can call
Open API routes subject to their own authentication and authorization. Internal
worker and session-authenticated administration routes are not promoted into SDK
methods by this release.

Validation uses mock HTTP responses and local workflow objects. The original
cycle failure was also checked against read-only production task records and
cycle responses. No production task was created, retried, resumed, or modified;
no backend/worker deployment is part of this package release. Provider-backed
execution of the 115 node types is outside the local serialization checks.
